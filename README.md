## Pipeline CI/CD

*COURSE*: 

> **Processo e Sviluppo Software**

*BRIEF DESCRIPTION*: 

> GitLab CI/CD pipeline for the Java application, structured into seven
> stages:
> 
> 1.  **Build:** In this stage, the project is compiled.
> 2.  **Verify:** During this stage, SpotBugs is executed for bug detection and CheckStyle for code style verification. The reports
> generated by these tools are saved as artifacts.
> 3. **Unit Test:** In this stage, only the project's unit tests are executed. The code coverage report is output to the corresponding
> job's console.
> 4. **Integration Test:** This stage exclusively runs the integration tests between the application and the database (Firebase).
> 5. **Package:** In this stage, the project is packaged into a JAR file, bypassing test execution in accordance with the guidelines. The
> JAR file is saved as an artifact.
> 6. **Release:** During this stage, a Docker image of the project is built and pushed to the Docker registry.
> 7.  **Docs:** In this final stage, the project's Java documentation is generated using Javadoc. The resulting report is saved as an artifact.
>     
> 
> Each stage leverages caching to optimize performance, reducing the
> overall execution time by over two minutes. Furthermore, relevant
> artifacts are retained for use in subsequent stages or for debugging
> purposes.

*TECHNOLOGIES & APPROACHES*: 

 - DevOps
 - Maven
 - Java
 - Docker
 - JUnit
 - CI/CD
 - Firebase
